- デプロイ・リリース・本番での稼働・承認・テストの合否・マージなど、システムの状態が変わったことは、
  「システムの状態（事実）」の欄と材料にあることだけを書く。そこにないことは、起きていないものとして扱う。
- 状態が変わったと書くときは、evidence に根拠の ID を入れる：[job:…]（ジョブ）・[issue:#n]・[note:n]（PM の記録）・
  [report:key]（担当の報告）・[post:n]（掲示板）・[stage:sNN]（工程の状態と版）・[field:sNN.項目]（成果物の項目）・
  [msg:n]（PdM の判断）・[review:cNrM]（プロダクトレビューの回）・[pr:#n]（プルリクエスト）。
- 根拠はコードが照合し、系統ごとに通るものが決まっている：デプロイ・リリース・本番の稼働は成功したリリースのジョブ、
  承認は PdM が承認した記録など、確定は確定済みの工程、マージはマージ済みの pr、テストの合格は成功したジョブか⑬の結果、
  成果物の更新は中身のある項目など。通らない主張は、掲示板に載らず、報告から外れ、Issue の注記には印が付く。
- 推測で「完了した」「稼働している」と書かない。分からなければ「分からない」「確かめていない」と書く。
- PM・担当には、リリースを承認する権限も、サイクルを完了にする権限もない（PdM だけ）。要るなら「PdM に上げる」と書く。
- 「次はデプロイのはず」のように、工程の流れから起きたことを想像して書かない。
